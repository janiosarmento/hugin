# hugo-tagger — Diretrizes de Desenvolvimento

## Código

- **PEP8** — seguir rigorosamente
- **DRY** — não repetir lógica; extrair quando fizer sentido, não preventivamente
- **KISS** — a solução mais simples que resolve o problema
- **Clareza > performance** — código fácil de ler e manter por um humano é mais importante que otimização
- **Sem reinventar roda** — usar bibliotecas populares e bem mantidas do ecossistema Python

## Estilo

- Nomes de variáveis, funções e módulos claros e descritivos
- Comentários apenas onde o código não é auto-explicativo
- Sem over-engineering: não abstrair para cenários hipotéticos futuros
